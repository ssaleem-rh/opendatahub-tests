# TC-E2E-001: Private git repo evaluation job end-to-end

**Objective**: Validate the complete user journey for submitting
an evaluation job with a private git repository, from API
submission through git clone, credential handling, job execution,
and metadata retrieval.

**Preconditions**:

- EvalHub API v0.4.0+ deployed with git storage source support
- Private test repository `evalhub-test-data-private` exists
  with evaluation datasets on the `main` branch
- Kubernetes Secret `git-test-creds` exists in the evaluation
  job namespace with valid HTTPS basic auth credentials

**Test Steps**:

1. Verify the `git-test-creds` Secret exists:
   `oc get secret git-test-creds -n <namespace>`
2. Submit an evaluation job via
   `POST /api/v1/evaluations/jobs` with `test_data_ref.git`
   specifying the private repository, `ref: "main"`, and
   `secret_ref: "git-test-creds"` <!-- pragma: allowlist secret -->
3. Verify the API returns a successful response with a job ID
4. Monitor the job pod until the git-clone init container
   completes
5. Verify the init container exited with code 0
6. Verify the Secret volume is mounted only in the init
   container (not in the evaluation container)
7. Wait for the evaluation job to complete
8. Retrieve the job via
   `GET /api/v1/evaluations/jobs/{id}`
9. Verify `git_commit_sha` is present and is a 40-character
   hexadecimal string
10. Verify the `test_data_ref.git` configuration in the response
    matches the submitted values

**Expected Results**:

- POST returns HTTP 200/201 with a job ID
- Git-clone init container completes with exit code 0
- Secret `git-test-creds` is mounted only in the init container
- Evaluation container has access to cloned files at
  `/test_data/`
- Evaluation job completes with a successful status
- GET response contains `git_commit_sha` matching a valid
  40-character SHA
- GET response preserves `repository_url`, `ref`, and
  `secret_ref` values
