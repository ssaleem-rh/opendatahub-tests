# TC-E2E-002: Public git repo evaluation job end-to-end

**Objective**: Validate the complete user journey for submitting
an evaluation job with a public git repository, verifying that
no credentials are required and that commit SHA provenance is
recorded.

**Preconditions**:

- EvalHub API v0.4.0+ deployed with git storage source support
- Public test repository `evalhub-test-data-public` exists with
  evaluation datasets and a tag `v1.0`

**Test Steps**:

1. Note the commit SHA that the `v1.0` tag resolves to in the
   public test repository
2. Submit an evaluation job via
   `POST /api/v1/evaluations/jobs` with `test_data_ref.git`
   specifying the public repository and `ref: "v1.0"` (no
   `secret_ref`)
3. Verify the API returns a successful response with a job ID
4. Monitor the job pod until the git-clone init container
   completes
5. Verify the init container exited with code 0 and no Secret
   volumes are mounted in the pod spec
6. Wait for the evaluation job to complete
7. Retrieve the job via
   `GET /api/v1/evaluations/jobs/{id}`
8. Verify `git_commit_sha` matches the known commit SHA for
   the `v1.0` tag

**Expected Results**:

- POST returns HTTP 200/201 with a job ID
- Pod spec contains no Secret volume mounts for git credentials
- Git-clone init container completes with exit code 0
- Evaluation container reads cloned data from `/test_data/`
- Evaluation job completes with a successful status
- GET response contains `git_commit_sha` matching the `v1.0`
  tag's commit SHA
- No `secret_ref` field appears in the response
