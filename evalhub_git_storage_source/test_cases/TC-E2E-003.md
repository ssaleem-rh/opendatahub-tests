# TC-E2E-003: Git sub-path evaluation job end-to-end

**Objective**: Validate the complete user journey for submitting
an evaluation job that clones only a sub-directory of a git
repository, verifying targeted dataset access and commit SHA
recording.

**Preconditions**:

- EvalHub API v0.4.0+ deployed with git storage source support
- Public test repository `evalhub-test-data-public` contains a
  sub-directory `datasets/subset-a/` with evaluation data files

**Test Steps**:

1. Submit an evaluation job via
   `POST /api/v1/evaluations/jobs` with `test_data_ref.git`
   specifying the public repository, `ref: "main"`, and
   `sub_path: "datasets/subset-a"`
2. Verify the API returns a successful response with a job ID
3. Monitor the job pod until the git-clone init container
   completes
4. Verify the init container exited with code 0
5. Verify that only files from `datasets/subset-a/` are
   available at `/test_data/` in the evaluation container
6. Wait for the evaluation job to complete
7. Retrieve the job via
   `GET /api/v1/evaluations/jobs/{id}`
8. Verify `git_commit_sha` is present and the `sub_path` value
   is preserved in the response

**Expected Results**:

- POST returns HTTP 200/201 with a job ID
- Git-clone init container completes with exit code 0
- Files at `/test_data/` correspond only to
  `datasets/subset-a/` content
- Files from other repository directories are not present at
  `/test_data/`
- Evaluation job completes with a successful status
- GET response contains `git_commit_sha` and preserves the
  `sub_path` value
